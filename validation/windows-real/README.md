# SuperDev Windows real-validation portable source

This directory is the immutable source of a portable Windows 10 22H2 x64 (build 19045) validation package. UBR and installed KBs are observations only; ESU support is not mechanically proven.

- Build on macOS with `go run ./cmd/build-windows-validation` from `agent/`.
- Copy the generated ZIP and checksum to Windows together with the two frozen installers.
- Follow `Runbook.md`; run `Prepare-Validation.ps1 -RuntimeInput <path>` before each lane, then use `Run-Validation.ps1` and `Cleanup-Validation.ps1` with that exact prepared backup.
- Campaign report schema v4 records `attempted` execution facts, required evidence, and the two-stage environment binding, then derives only `NOT_RUN`, `BLOCKED`, `PASS`, or `FAIL`; callers must never synthesize verdict strings.
- Installer artifact identity is reported separately from install/start/stop/uninstall lifecycle execution.
- `Invoke-InstallerLifecycle.ps1` only requests the next fixed action. The packaged driver accepts exactly four ordinary JSON facts (`01-install.json` through `04-uninstall.json`), derives every verdict from their execution/evidence fields, and rejects missing, corrupt, out-of-order, extra, or cross-campaign facts. The helper owns `.installer-lifecycle.active.lock` from before action dispatch until the helper, UAC child, state observation, and result write finish, even if the driver exits unexpectedly. Operators must not retry while that active lock is held; after release, only the four ordinary facts and read-only machine state decide whether retry is safe. The lock file is not evidence or a verdict, and an unlocked leftover file carries no state.
- `core_only` is a diagnostic lane that executes and reports the same core/provider/tool/pipeline surfaces with zero installer checks or lifecycle facts. Only explicitly named capability blockers may remain `BLOCKED`; it cannot satisfy final installer acceptance.
- Functional lanes collect one human-entered test credential through the PowerShell hidden prompt, create a campaign-owned in-memory Agent lease only around `get_debug_credentials`, and never put the value in runtime input, command arguments, logs, backups, or evidence.
- Prepare archives a v2/34-key pre-install manifest A before any installer or user-state mutation: 24 local facts are collected and 10 product facts stay explicitly deferred. A validates and digests only pre-install-stable input/plan fields; fresh Host ID and governance may remain placeholders and are excluded from that digest. After product bootstrap, B requires the complete input/governance contract, rejects any stable-subset drift, binds A by manifest digest, and persists a re-derivable `environment-manifest-comparison.json`. MSI stops after A; `core_only` follows the same A→B contract while keeping every installer fact `NOT_RUN`.
- Browser identity is read from executable metadata, SHA-256, and Authenticode without launching Chrome or Edge. JVM adapter identity requires an operator-frozen command plus SHA-256; expected values must be frozen before the independent collector runs.
- Environment admission accepts only the collector-owned in-memory result. Persisted JSON supports structural and drift review but cannot mint a new final admission after public digests are recomputed.
- Every persisted report is re-derived from execution facts, prerequisite facts, and evidence obligations before it is written or finalized; stored status strings are never trusted as input.
- The report persists the frozen scenario/step/cleanup and 75-tool coverage catalog; missing, duplicate, or remapped rows are rejected before any aggregate result is derived.
- Cleanup PASS is bound to the exact prepared `baseline.json`: the finalizer recomputes the whole-file and six category hashes, then requires the manifest, cleanup report, campaign ID, and lane to agree.
- Do not add runtime input, installers, backups, or results inside the extracted package.
- A macOS build may report only `package_verified`. It cannot produce Windows MCP or provider verdicts.
